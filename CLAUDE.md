# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Mind PKM (formerly Freeplane PKM): a standalone Windows application (Rust + iced) for a personal knowledge management (PKM) system around a mind map. It replaces the Freeplane add-on [unhurried/freeplane-pkm](https://github.com/unhurried/freeplane-pkm) and must stay compatible with it: the same `.mm` files (Freeplane can still open them) and the same document directory layout.

## Commands

```bash
cargo test                                 # all tests
cargo test search::                        # one module
cargo clippy --all-targets -- -D warnings  # CI fails on any warning
cargo fmt --check
cargo build --release                      # target/release/mind-pkm(.exe)
cargo build --release --target x86_64-pc-windows-gnu   # Windows exe from Linux (needs mingw-w64)
cargo test --release --lib --config 'profile.release.package.iced_core.debug-assertions=true' perf -- --ignored --nocapture --test-threads=1   # the benchmark (app/perf.rs)
```

The first build downloads the IPADIC dictionary (lindera's `embed-ipadic`; embedded in the binary) into `.cache/lindera/` (`.cargo/config.toml`), which every profile, target and toolchain shares and `cargo clean` keeps. A push to `main` releases the `Cargo.toml` version as tag `v<version>` unless that tag exists (`.github/workflows/build.yml`, Windows runner) - bump the version to release.

The Rust toolchain is pinned in `rust-toolchain.toml` (CI reads it too); bump it on purpose, fixing new lints in the same change. In Claude Code cloud sessions `.claude/hooks/session-start.sh` installs that toolchain (rustup), Node.js and the OpenSpec CLI via [mise](https://mise.jdx.dev) (`mise.toml` pins the versions; CI uses the same file), Xvfb, xdotool and ImageMagick, and prebuilds the tests. `mise install` also installs the toolchain from `rust-toolchain.toml` (`idiomatic_version_file_enable_tools` in `mise.toml`), which is how the [devcontainer-claude-code](https://github.com/unhurried/devcontainer-claude-code) dev container gets it (README, Dev Container); the hook and CI install only Node.js and the OpenSpec CLI through mise.

## Structure

- `src/lib.rs` holds every module; `src/main.rs` only starts the app. `tests/` holds integration and property tests (proptest) against the library.
- `src/xml.rs` - minimal XML DOM. Writes like Freeplane's own writer: no XML declaration, every non-ASCII UTF-16 unit as `&#x..;` (so characters outside the BMP become surrogate-pair references, which the reader recombines), newlines in attributes as `&#xa;`.
- `src/mindmap.rs` - the `.mm` model. Nodes live in an arena (`NodeId` = index, never reused - not even after an undo: `Doc` pads a restored map with `reserve_ids`, so replace `Doc::map` only through `Doc`); nodes and the ID index sit behind `Arc`s, so a copy (one per undo step) shares everything it doesn't change - mutate nodes only through `node_mut`; each node keeps all its XML attributes and non-node child elements (`Item::Xml`) in order, so anything the app doesn't understand round-trips unchanged. `MindMap::parse(..).to_xml()` must reproduce a Freeplane-written file byte for byte (see the round-trip test) - keep it that way.
- `src/error_log.rs` - the error log `mind-pkm-error.log` next to the exe (temp folder if not writable; rotated to `.old` past 1 MiB): `install` (panic hook, called first in `main`) and `write` (also for a failed start and a failed index update). It never fails or shows anything itself; in tests `write` goes nowhere unless `redirect` points the thread's log at a temp dir. Only application failures belong there - not the dialog messages or other status bar messages.
- `src/paths.rs` - `LINK` URI <-> path (relative to the map file, percent-encoded like `java.net.URI`; `file:/C:/...` for absolute ones) and path comparison (`key`: normalized, case-folded on Windows, like `java.io.File#equals`).
- `src/pkm/` - the add-on's `Utils.groovy` and menu scripts, UI-free: an `Err(String)` is the message shown to the user, and commands that ask first are split into a check and an execution (`delete_targets` / `delete_question` / `delete_execute`). Error messages are the add-on's, verbatim.
- `src/pkm/assets.rs` - the assets pane's file operations: the folder tree, renaming and deleting (through a given remover), only strictly inside the document directory.
- `src/pkm/next_steps.rs` - `snapshot` (UI thread) → `compute` (background: reads pages) → `apply` (UI thread; skips nodes deleted/renamed meanwhile).
- `src/search/` - tantivy index under `<docDir>/.search-index/tantivy/` + `tantivy.meta` (schema version + mtimes for incremental updates); the add-on's Lucene index (`lucene/`, `files.meta`) is deliberately left alone. Bump `INDEX_SCHEMA_VERSION` whenever the analyzer or fields change incompatibly; `analyzer.rs` tests pin the tokenization.
- `src/markdown/` - the page editor's Markdown, UI-free. The page text is the single source of truth: `parse.rs` splits it into blocks with byte ranges (pulldown-cmark with offsets; list items flattened; every block of a quote, and every block of a list item after its first, a block of its own inside its containers (`Block::outer`); lenient link destinations; front matter at the start of a page only; `parse_masked` leaves out one byte - a marker typed but not determined yet; `reparse` (`parse/reparse.rs`) parses an edited text again only from an element after a blank line before the change to the first one after it that still starts where it did, else whole - every result checked against the whole parse in debug builds), `content.rs` turns a block into inline runs that map back to source offsets (clicks), `edit.rs`/`format.rs` are the editing rules as functions returning the edited text and selection (`edit::nested` applies one to a block inside quotes or list items: on the container's lines without their prefixes, putting them back; `edit::CodeBody` is a code block's code the same way, without its fences), `table.rs` the table model (cells as Markdown, written padded by display width), `paste.rs` what pasting puts in (HTML as Markdown, a table as cells, text as it is), `html.rs`/`export.rs` HTML and PDF (Edge/Chrome headless) export, `render.rs` math (latex-rust) and Mermaid as SVG, `lists.rs` a list's blank lines (`tidy`: an edited list written tight, or loose only when a block in an item needs a blank line - the parser decides, by parsing the tight form), `live.rs` what the block being edited shows (rendered text, with the Markdown of the inline elements at the cursor), the mapping of shown offsets and edits back to the source, and when a typed marker is not determined yet (`undetermined`). Edits splice the source; nothing is regenerated from a tree, so untouched bytes (BOM, CRLF via `page.rs`) stay.
- `src/app/` - iced (0.14) UI, an `iced::daemon` with several windows: the map's and one per open page; a window's events come as `Message::Window` with its id, and `update` turns the map window's into its `MapMsg` and hands an editor window's to its `Editor`. `mod.rs`: `App`, `Message` / `WindowEvent` / `MapMsg`, `update` (dispatches each message to the module of its topic); `doc.rs`: `Doc` (an open map: selection, filter, layout, undo) and the edits that only touch the map; `command.rs`: `Command` and `run_command`; `keys.rs`: keyboard handling, key bindings (`command_for_key`); `dialog.rs`: dialogs and their outcome; `node_edit.rs`: a node's text edited in the node on the map (new nodes and Edit Node Text; not a dialog): `NodeEdit` holds the node and its `text_editor::Content`, the layout is made with the text typed so far (`doc::Draft`; the node is shown even if the filter hides it), Enter / a click elsewhere confirm (`MapMsg::confirms_node_edit`), Esc cancels, and the map's keys don't act meanwhile; `file.rs`: new/open/save, unsaved-changes guard; `viewport.rs`: relayout, scrolling, panning, zooming (`MapViewport`: the zoom with the text sizes measured at it, the scroll position - followed after every event without a message, zooming and panning start from it - and the one the nodes near the visible part are built for, a pan; `ctrl_wheel.rs` catches Ctrl+wheel over the map); `drag.rs`: moving nodes by drag and drop (drop position, `Doc::move_nodes`); `ime.rs`: the caret rectangle given to the IME, so the text being composed (drawn by the shell, bottom-aligned to it) lines up with the text around it - wrap a `text_editor` on a line taller than the default in `ime_aligned`; `view.rs`: rendering, menus (`MENUS`), node measuring - widgets only for the nodes near the visible part of the map (`App::near_view`: the view as last told or scrolled to, with a margin; the map is told where it is when the visible part comes within half the margin of the edge of those, `scroll_watch`), the edges drawn whole on one canvas; `placed.rs`: the widgets placed at points, layered like a stack and keyed, so that a node's widget state (its shaped text) stays with it as the set of nodes shown changes; `keyed_column.rs`: a column whose children keep their widget state by key (iced's `Column` hands it out by place: a block added in the middle had every block after it shaped again) and tell where they were laid out - the page editor's column of blocks; `scroll_watch.rs`: where a scrollable is scrolled, told only when the visible part leaves a band, after any event (a redraw too, so scrolls by operations are told before the window is drawn), followed after every event without a message (`tracking`), and kept in place as the content is laid out anew (`anchor`: the content scrolled right after it is laid out) - the page editor's page and the map; `ui.rs`: what the map window and the editor windows draw alike - the menu bar and menus, right-click menus (`context_menu`, entries taken from the menu bar's items), dialogs (each window passes its `MenuStyle` / `DialogStyle`) - and the zoom steps; `after_draw.rs`: a message sent once when the window is drawn next (a view asking for another, as iced asks for the subscriptions before it builds the views); `right_press.rs`: where the right button went down (a window's root records it before the widget under the pointer says which right-click menu opens); `press_point.rs`: where a left or right press lands (in the window or in a widget), told only on the press - instead of following the pointer with `on_move`; `profile.rs`: timings of messages and of every window's view, diff, layout, draw and events, written to the file `MIND_PKM_PROFILE` names (else nothing is timed); `perf.rs`: the benchmark - the app on a large map with a long page open, every window rebuilt after each message as iced does, with a headless renderer (`iced_runtime`'s `UserInterface`), and tests that pointer moves send no messages, that the map builds the nodes and the page the blocks near what they show, that the page and the map tell where they are scrolled only near the end of what they built, that blocks of unknown height are measured a few at a time and that the block at the top of the visible part stays in place (the harness moves the map's scrollable where the app scrolled it and sends `EditorMsg::Measure` while the page has blocks to measure; it runs no other task); `layout.rs`: pure mind map layout; `search_panel.rs`: F6 panel; `editors.rs`: the editor windows as the app keeps them (opening a page in one, handing them their messages and doing their `Effect`s, the shared `EditorPrefs`, following what the PKM commands do to their files); `tests.rs`: the app driven by its messages (keys, commands, dialog answers, background results) without a window - add a test there for a UI flow (`test_support.rs`: `send`, key events). `editor/`: the page editor window - `mod.rs` (`Editor`, `EditorMsg`, effects on the app), `page.rs` (the page: text, blocks, the active region - edited rendered through `live::Display`, a code block's code (`CodeBody`) or another code-like block's source in a `text_editor` - every edit spliced back, the undetermined marker left out of the parse until the element is determined, undo), `live_text.rs` (the widget editing rendered text: layout from `flow.rs`, caret, selection, mouse, keys through the same bindings, IME), `flow.rs` (line breaking and caret/hit geometry over measured text runs and objects, pure), `keys.rs` (menus, shortcuts, the text editor's key bindings; menu shortcuts are tested against the bindings), `column.rs` (what the page column shows: the blocks with the active region in their place, their containers, the gaps between them and their keys - a block's its source, never an offset, which every edit above it changes; pure), `near.rs` (which of them get widgets: those near the visible part of the page (found from the block at its top as the page last told, `Editor::visible`), the active region and a block scrolled to wherever they are, and of those whose height is not known the nearest few - a batch with every view, which asks for the next message when it is drawn while some are left (`after_draw.rs`, `EditorMsg::Measure`); the others take their room together, from the heights the column last laid out, kept by key for a width and zoom - at another one, or after a render came in for a block with math or a diagram, a block takes a guess (its height before, scaled as its estimate is) until it is measured; and how far the page scrolls, right after it is laid out, for the block at the top of the visible part to stay in place (`shift`); pure), `view/` (rendering: `document` the page column, `blocks`/`inline` rendered blocks and their text, `active` the region being edited, `chrome` bars, menus, outline and dialogs, `theme` colors, fonts and sizes, `hit` mapping a click to the source, `table_widths` a table's column widths - each as wide as its widest line up to a maximum, widened to the page or scrolled sideways - alike for the rendered table and the one being edited, with the measured lines cached in the editor), `highlight.rs` (the active block's source), `tables.rs` (the table being edited; `TableUi` what the window keeps meanwhile), `find.rs`, `assets.rs` (the assets pane: the `<name>.assets/` tree read in the background, the app doing rename/delete, dragging items onto the page), `press_relay.rs` (what a press on a rendered block hands the text editor that replaces it: the click and the drags with the button held), `scroll.rs`, `render.rs` (background SVG cache), `clipboard.rs` (arboard behind a trait; tests use a memory clipboard), `tests/` (the editor driven by its messages, a file per topic; shared helpers in `tests/mod.rs`). The layout is recomputed in `update` after every message (`relayout`), never in `view`; text sizes are measured with the same paragraph engine the text widget uses and cached per text. Zooming lays the map out at the zoomed size (font, paddings, gaps all scaled), so layout coordinates are always screen pixels; the text size cache holds the sizes at 100%, which `view::text_at_zoom` scales to the zoom (the text layout is not hinted, so a text takes the same lines at every zoom - a test checks every zoom step), so zooming measures nothing again.

- `assets/codesign.cer` - the public half of the self-signed code signing certificate (`tools/make_codesign_cert.sh`); the workflow signs the exe with the `CODESIGN_PFX` / `CODESIGN_PASSWORD` secrets. The private key never goes into the repository. README documents the thumbprint.
- `assets/icon.*` - the application icon, drawn by `tools/make_icon.py` (Pillow; rerun it after changing the drawing). `build.rs` embeds `icon.ico` into the Windows exe (winresource; `windres` from mingw-w64 when cross-compiling), and `icon-64.rgba` is the window icon.

## Conventions (not discoverable from the code alone)

- Document directory: `root > config > docDirPath > <path>`. Page node: text links `<docDir>/<text>.md`; directory node: `<docDir>/<text>/`; attachments in `<text>.assets/`. Pages are UTF-8 with a BOM (`markdown::page`: `read_page`/`write_page`, and `PageText` for the editor). Dates are `yy/MM/dd`.
- Up to 3 items under a page's `### Next Steps` are synced into the node's children; ToDo items (`<item> (<page>)` linking the page) whose text is gone from *all* of the page's Next Steps are deleted; Due Today / Past Due are filled from all items. The refresh runs on F12, and every 5 minutes after the map changed.
- The map is laid out to the right only (`layout.rs` ignores `POSITION`); children added, pasted or moved under the root get `MindMap::set_right`. An existing node's `POSITION` is never rewritten unless it is moved.
- The map changes only through `Doc` (its fields are private): `Doc::change` records an edit for undo, `Doc::try_change` one that may fail (recorded only if it succeeds), `change_recorded_if` / `change_or_revert` one that may change nothing. Changes that are no undo step say why in their name (`unfold_to_navigate` and `reveal`: navigating; `set_new_node_text`: part of the node's creation). Recording a change also marks the map as edited, which is what schedules the periodic refresh, and keeps the selection for Undo. The refresh applies its own changes through `Doc::apply_refresh`, which records no undo step: it applies them to every map of the undo/redo history too, so Undo takes back only the user's changes. Undo entries carry a serial number (`new_child` / `new_sibling` return it); take back a specific change by its serial (`Doc::cancel_new_node`), never by popping the latest entry. A selected node that is gone hands the selection to its nearest neighbour (`Doc::relayout`), so nothing needs to fall back to the root.
- File I/O and indexing run via `blocking(...)` (tokio blocking pool), never in `update`/`view` - except the small, synchronous file operations of the PKM commands and of opening, saving and reloading a page in the editor.
- After any message, of any window, iced builds every window's view again, compares and lays it out: keep messages few (no message for every pointer move or step of the wheel - follow the pointer only while something is dragged, take a press's place with `press_point`) and views cheap (keep slow results such as code highlighting or the status bar's counts in a cache, and widget state with its widget - a widget whose state is lost shapes its text again; the map is laid out again only when the map's version, the filter, the zoom or the text being edited changed - the last measuring only the node being edited again - and builds widgets only for the nodes near its visible part; the page editor builds only the blocks near the visible part of the page). Check with the benchmark (`perf.rs`).
- The page editor never rewrites a page wholesale: an edit replaces the source range it covers (`edit::splice`), and the page is re-parsed after every change (`Document::reparse`: in part where that gives the same as the whole parse). Pages are written with their BOM and line endings as read. The one exception is the blank lines of the lists an edit changed: `Page::apply` (editing rules; `set_text` is a plain replacement for find and replace and the source mode) and leaving a block typed in tidy them (`lists::tidy`), mapping offsets through its `Shift`.
- Pull requests (title and description) are written in English.
- F1-F12 must keep the add-on's assignments (README table). Adding a command means: `Command` variant, `MENUS` entry, `command_for_key` if it has a shortcut, and the README; tests in `keys.rs` check that the menu shortcuts, the key bindings and the README's PKM table agree.

## Guardrails (never)

- Never remove, move or overwrite anything outside the document directory, nor the document directory itself. Paths built from node text must pass `paths::is_strictly_inside` (a node is a page/directory node only then), and deleting goes through `commands::delete_execute`, which checks again and takes the remover as a parameter. Every deletion of the app (PKM Delete, the assets pane) uses the one remover `App::new` is given: `recycle` (to the Recycle Bin) when the app runs, `test_support::remove_in_temp` in tests, which removes files only inside the temporary directory - never the real trash. `delete_never_leaves_the_document_directory` must keep passing; extend it rather than weaken it.
- Never change the `.mm` reader/writer without the byte-for-byte round-trip test passing, and never reword a ported command's message.
- Never skip, ignore or loosen a test, lint or `openspec validate` to get to green; fix the cause.

## Specifications (OpenSpec)

The behavior contract lives in `openspec/specs/<capability>/spec.md` (OpenSpec, `spec-driven` schema; `openspec/config.yaml` holds the project context). Capabilities: `mindmap-file`, `mindmap-editing`, `application-shell`, `document-management`, `task-management`, `map-filter`, `document-search`, `page-editor`, `page-assets`, `markdown-rendering`, `table-editing`, `image-insertion`, `page-export`.

- A change of behavior starts as an OpenSpec change (`/opsx:propose`, or `openspec/changes/<name>/` with proposal, delta specs, design, tasks), is implemented with `/opsx:apply`, and is merged into the specs with `/opsx:archive`. Pure refactors and tooling changes need no spec change.
- Keep the specs about observable behavior - no module or function names.
- `openspec validate --specs --strict` must pass (CI runs it). The CLI is installed by `mise install` (`mise.toml`).

## Definition of done

`cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test` and `openspec validate --all --strict` pass, and `openspec/specs/` describes the new behavior. For UI changes, run the app (it works under Xvfb on Linux; `xdotool` can drive it) and look at it.
